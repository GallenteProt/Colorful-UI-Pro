# WeaponRadialMenu

Радиальное меню оружия для DayZ 1.30: арсенал для всех игроков. Сервер сам создаёт предметы.

## Как пользоваться

- Нажмите **~** (Grave, kGrave; клавиша по умолчанию, меняется в настройках управления, группа «Радиальное меню оружия»), чтобы открыть колесо. Повторное нажатие **~** или **Esc** закрывает его. Короткое нажатие, удерживать не нужно. Пока колесо открыто, ванильное действие **~** (показать/скрыть панель быстрого доступа, по удержанию левая часть HUD) не срабатывает; показать или скрыть панель можно, как раньше, ванильной настройкой панели быстрого доступа (Настройки, Игра; Show quickbar).
- Выбор цифрой: у каждой ячейки в левом верхнем углу карточки маленький номер. Нумерация идёт по часовой стрелке от верхней ячейки, ячейки «Назад» и «След.» нумеруются так же, как остальные («След.» всегда сверху, поэтому имеет номер 1). Клавиши **1-9** = 1-9, **0** = 10, **-** = 11, **=** = 12, цифры на малой клавиатуре (NumPad 0-9) работают так же. Цифра действует как ЛКМ по ячейке. Пока меню открыто, цифры не переключают слоты быстрого доступа. Номера обновляются при каждой смене уровня или страницы.
- Корневое колесо: вокруг категории оружия, **снизу** ячейка «Обвесы» (для оружия в руках).
- Управление мышью на ячейке оружия (в категории и в колесе вариантов):
  - **ЛКМ**: взять оружие сразу (у группы цветов выдаётся основной класс ячейки). Цифра на клавиатуре действует так же, как ЛКМ.
  - **СКМ** (клик колёсиком): у ячейки-группы с значком «два квадрата» открывает колесо цветовых вариантов; у обычной ячейки ничего не делает.
  - **ПКМ**: взять оружие и сразу открыть «Обвесы» оружия в руках (ждёт ответа сервера и появления оружия в руках; если это же оружие уже в руках, просто открывает «Обвесы»; при отказе сервера остаётся на месте и показывает сообщение).
  - ПКМ на любой другой ячейке: «Назад».
- Кнопка выбора на геймпаде: выбрать. **Назад** (ячейка снизу, **Backspace**, ПКМ вне оружия, кнопка «назад» геймпада, цифра ячейки «Назад»): на странице после первой возвращает на предыдущую страницу того же уровня, на первой странице на один уровень вверх. Подсказка в центре колеса у ячейки «Назад» говорит, что именно она сделает. После выдачи меню остаётся открытым.
- Внутри «Обвесов»: ячейка «Магазины» (магазины текущего дула) и по одной ячейке на каждый слот оружия. Внутри слота список совместимых предметов; установленный подсвечен.
- Ячейки без текста: готовая картинка предмета (оружие, вариант, магазин, обвес), значок категории или кнопки навигации. Зелёная подсветка: оружие в руках или установленный обвес. Маленький значок «два квадрата»: у ячейки несколько вариантов (цветов), СКМ открывает ещё одно колесо с вариантами, «Назад» возвращает на ту же страницу.
- Название под курсором, заголовок уровня и короткие сообщения о результате показываются в центре колеса. Одинаковые названия вариантов получают суффикс из имени класса.
- Не больше 8 позиций на странице. Ячейки «Пред. страница» нет: её роль у «Назад» (снизу, 6 часов). Ячейка «След.» стоит строго напротив, сверху (12 часов): страница со «След.» всегда полная (1 «Назад» + 8 + 1 «След.» = 10 карточек, чётное число), поэтому она ровно на верхней позиции. На корневом колесе на второй и последующих страницах нижняя ячейка «Обвесы» заменена на «Назад» (предыдущая страница).
- Без оружия в руках ячейка «Обвесы» неактивна. Меню не открывается поверх другого меню, при смерти, без сознания, в наручниках, в транспорте, при поднятом оружии.

## Выдача (правила сервера)

- Клиент отправляет только намерение (класс, слот). Игрок берётся из отправителя RPC, всё проверяется на сервере: состояние игрока, класс в каталоге, слот и совместимость для предмета в руках на сервере, ограничение частоты.
- Занятые руки: текущий предмет убирается в инвентарь, если места нет, кладётся на землю, затем выдаётся оружие. Занятый слот обвеса или магазина: старый предмет уходит в инвентарь, иначе на землю. Если новый предмет создать не удалось, старое состояние сохраняется, игроку приходит сообщение. Предметы игрока никогда не удаляются.
- Лимит выдачи: по умолчанию 30 предметов на игрока. При превышении удаляется только самый старый выданный предмет, который лежит на земле, без родителя и без чужого содержимого. Если такого нет, выдача отклоняется.
- Учёт выданного хранится в памяти сервера и сбрасывается при рестарте.

## Каталог

Строится один раз на сервере при старте, частями по кадрам (много модов не вешают сервер). Пока он строится, меню показывает «Загрузка...».

- Оружие: `CfgWeapons`, `scope = 2`, наследует `Weapon_Base`, имя не `*_Base`/`*dummy*`, не `Archery_Base` (луки и арбалеты не огнестрел).
- Обвесы: `CfgVehicles`, `scope = 2`, `inventorySlot` (строка или массив) пересекается с `attachments[]` оружия без учёта регистра.
- Магазины: `magazines[]` текущего дула оружия, `CfgMagazines`, `scope = 2`. Оружие с внутренним магазином ячейки «Магазины» не имеет.
- Названия берутся у клиента из `displayName`, поэтому каждый видит свой язык. Списки отсортированы по имени класса.
- Варианты: классы одного списка (категория, слот, магазины дула) склеиваются в одну ячейку, если у них одинаковый путь `model` (не пустой, не dummy) И выполняется одно из: одинаковый сырой `displayName`, один класс наследует другой, общий непосредственный базовый класс. У магазинов дополнительно совпадает `count`. Лицо ячейки: предок остальных, иначе самое короткое имя, затем по алфавиту. Выдаваемый класс всегда проверяется сервером точно.
- Предметы в ячейках показываются живым 3D-превью (`ItemPreviewWidget`, `priority 200` в `wrm_card.layout`). Значки категорий и навигации лежат в `gui/textures/*.paa`.

### Категории (эвристика, порядок важен, первое совпадение побеждает)

0. `categoryOverrides` из JSON.
1. гранатомёты, 2. пистолеты, 3. дробовики (по цепочке классов или по патронам 12/20 калибра), 4. пистолеты-пулемёты, 5. снайперские/марксманские (по цепочке классов или по крупному калибру у не автоматического оружия), 6. штурмовые (по цепочке классов или режим `FullAuto` у `Rifle_Base`), 7. винтовки/карабины (остальной `Rifle_Base`), 8. прочее.

Токены лежат в `scripts/3_Game/WRMClassifier.c`. Пустые категории скрываются.

## Настройка

Файл `$profile:WeaponRadialMenu/config.json` создаётся с настройками по умолчанию. Если он существует, но не читается, он **не перезаписывается**, в лог пишется ошибка, в памяти используются значения по умолчанию. Пример: `config.example.json`.

| Поле | Смысл |
|---|---|
| `cooldownMs` | минимальный интервал между выдачами одного игрока |
| `maxIssuedPerPlayer` | лимит выданных предметов |
| `collapseColorVariants` | устарело и игнорируется (варианты теперь всегда склеиваются по модели), поле допустимо в старых файлах |
| `categories[]` | `id`, `name` (пусто = по умолчанию; можно `#STR_КЛЮЧ` или текст), `order`, `hidden`; можно добавлять свои `id` |
| `categoryOverrides[]` | `"Класс=idКатегории"` |
| `weaponInclude[]` | принудительно добавить класс оружия (`scope 2` обязателен) |
| `weaponExclude[]` | исключить класс или префикс `Prefix*` |
| `attachmentInclude[]` / `attachmentExclude[]` | то же для обвесов и магазинов |

Изменения читаются при старте сервера.

## Установка

Один PBO с префиксом `WeaponRadialMenu` (файл `$PBOPREFIX$`), мод нужен и на сервере, и на клиенте. Зависимости только ванильные (`DZ_Data`, `DZ_Scripts`). Кнопка объявлена в `data/inputs.xml`.

## Совместимость

Используется собственный `UIScriptedMenu` (id 5718605) и общий ванильный `RadialMenu`. `GesturesMenu` и эмоции не изменяются, SFP_anim_system и Dabs Framework не затрагиваются. Раскладки колеса взяты из ванильных файлов жестов.

## Скрытые классы ванили 1.30

Недоделанные классы бросают исключения скриптов в руках и по умолчанию не выдаются:
AKM_TESTBED, DartGun, LAW, M249, RPG7, Shockpistol, Shockpistol_Black, Groza, GP25, GP25_Standalone,
M203, M203_Standalone, Trumpet, UnderSlugGrenadeM4. Вернуть класс можно через `weaponInclude`.
